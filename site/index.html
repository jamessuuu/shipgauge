Method notes: byte counts here use the public Resource Timing API, not Chrome DevTools Protocol. Confirmed live against huggingface.co (2026-08-15): it sends no Timing-Allow-Origin, so the browser zeroes out both transferSize and decodedBodySize for those cross-origin requests — not just the transfer size, as you might expect. When a request's real duration proves bytes moved but both size fields read zero, this page reports it as size unknown (opaque) and excludes it from the byte total rather than counting it as zero or guessing — the number shown is a floor, not the true total, whenever that warning appears. The repo's own results (results/results.json) were measured via CDP, which sees every byte regardless of CORS/TAO headers — treat that as authoritative over this page for exact figures. Execution-provider readback does not have this limitation: it works identically here and in the harness, counting real GPUQueue.submit() calls rather than trusting the device string you asked for.
